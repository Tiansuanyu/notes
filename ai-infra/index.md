# AI Infra Overview

AI Infra 关注的是模型怎样变成可训练、可推理、可测量的计算过程。这里不按模型名字收集论文，而是围绕张量形状、并行方式、注意力内存和运行时边界整理跨任务可复用的机制。

SLAM 中的 DINOv2、匹配网络或前馈三维模型会引用这些计算原理，但算法的输入输出、几何约束和实验结论仍应留在 [SLAM](../slam/)；机器人板卡上的驱动、相机链、进程调度与持续负载则归入 [Robotics Systems](../robotics-systems/)。

## 1. 从模型图回到张量与计算

以视觉 Transformer 为例，输入图像先被切成 patch 并投影为 token。若图像大小为 $H\times W$、patch 边长为 $P$，忽略特殊 token 时序列长度近似为

$$
N=\frac{H}{P}\frac{W}{P}.
$$

batch 为 $B$、隐藏维度为 $D$ 时，主干激活常以 $[B,N,D]$ 表示。多视图和视频还会引入视图/时间维，或者把它们折叠进序列。要分析显存和时延，首先应记录实际张量怎样 reshape，而不是只看“输入分辨率”和参数量。

标准全局 self-attention 的注意力矩阵随 $N^2$ 增长。图像长宽都放大两倍时，token 数约变为四倍，注意力矩阵规模则可能变为十六倍。窗口、稀疏或线性注意力会改变这个关系，但必须按具体实现确认；模型用了 Transformer 不等于每层都承担完整全局注意力。

## 2. 三条近期学习主线

### Transformer 的数据与计算

这一主线会从 token、embedding、Q/K/V、self/cross attention、MLP 和位置编码出发，用张量形状连接图像 patch、多视图与视频。重点是回答：分辨率、序列长度、batch、特征宽度分别怎样影响 FLOPs、激活和显存。

### Attention、KV Cache 与流式推理

需要把三类问题分开：

- 全局、因果或窗口注意力决定模型在语义上能访问哪些上下文；
- KV cache 决定已计算状态怎样复用、保留或淘汰；
- FlashAttention、FlashInfer、分页缓存等实现优化计算和内存访问，不自动改变模型学到的任务。

LLM 逐 token 生成与视觉逐帧处理都可能复用历史状态，但两者的输出节奏、缓存索引和时空一致性不同，类比时不能把“上一帧特征”直接等同于“上一批文本 token”。

### 训练与推理的计算边界

训练需要前向、损失、反向、优化器状态和参数更新；推理通常只保留前向所需状态。冻结、微调、自监督、自蒸馏和教师—学生描述的是不同训练关系，不应仅从最终模型大小判断训练成本。

DDP 属于这条主线，而不是孤立的一段 API 示例。数据并行中每个进程持有模型副本，处理不同 local batch，并在反向阶段同步梯度；若有 $N$ 个进程，且各进程 batch 一致，则

$$
B_{global}=N B_{local}.
$$

这个公式不说明有效 batch 的全部语义：梯度累积、最后一个不完整 batch、数据采样器和损失归一化都会影响结果。模型并行、流水线并行和上下文并行则拆分模型或序列，不是“DDP 换个名字”。

## 3. 性能数字先定义边界

同一个“推理耗时”可能只覆盖网络 kernel，也可能包含采集、解码、resize、归一化、主机—设备拷贝、后处理和同步等待。报告前至少说明：

| 维度 | 需要记录 |
| --- | --- |
| 输入 | batch、分辨率、序列/视图长度、数据类型 |
| 模型 | commit、权重、导出图、动态/静态 shape、量化方式 |
| 运行时 | 框架、编译器、驱动、设备与功耗/频率状态 |
| 计时 | warm-up、同步点、样本数、端到端边界、P50/P95 |
| 内存 | 权重、激活、cache、workspace，以及峰值的测量工具 |
| 正确性 | 与基线输出的误差、任务指标和失败样本 |

吞吐与单请求延迟也不是同一目标。增大 batch 可能提高设备利用率，却增加排队和尾延迟；异步流水线可能提高整体帧率，但必须记录输出对应的输入时间戳。

## 4. 通用优化与实际部署的分工

图融合、算子选择、精度格式、量化、缓存与 batch 策略属于可复用的计算问题；具体板卡能否执行某个算子，则取决于导出图、编译器、运行时、驱动和硬件版本。CUDA 上的 kernel 数字不能直接外推到 ARM CPU、OpenCL GPU 或 NPU。

实际 CAM-3576Q38 上的 BSP、设备树、RKNN 工具链、温控和测量边界见 [Firefly CAM-3576Q38：硬件、BSP 与部署边界](../robotics-systems/deployment/)。该页会把板级事实与 SoC 理论能力分开；这里后续只主讲跨平台的 Transformer 计算与训练/推理机制。
